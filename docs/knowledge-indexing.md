# Knowledge Indexing

The workbench indexes local knowledge into two generated TypeScript files:

```text
workbench/src/generated/knowledgeUniverse.generated.ts
workbench/src/generated/knowledgeIndex.generated.ts
```

They are generated by:

```text
workbench/scripts/build-knowledge-universe.mjs
```

By default the generator reads the public knowledge base:

```text
knowledge/
```

If `knowledge/` is missing, it can fall back to the private local backup:

```text
knowledge_backup/
```

For explicit runs:

```bash
FAME_KNOWLEDGE_SOURCE=public npm run generate:knowledge
FAME_KNOWLEDGE_SOURCE=private npm run generate:knowledge
```

## Index Layers

```text
Knowledge roots
-> route shards by root/subject
-> file entries
-> headings
-> redacted excerpts
-> keywords
```

The 3D view renders a level-of-detail overview:

```text
global root
-> knowledge roots
-> subject shards
-> representative sample files
```

The full file index is used for drill-down and search, not for drawing every node at once.

## Search

The Workbench search is deliberately scoped:

- 3D search covers universe nodes, route shards, file titles, headings, keywords, and paths.
- 2D search covers local route nodes and FAME edges.
- Selecting a 3D result selects the matching node or shard.
- Selecting a 2D result opens the local route detail and highlights the matched node or edge.

This keeps large graphs navigable without forcing a full graph traversal into the UI or the agent context.

## Privacy

The generator redacts common API key and token patterns in excerpts. This is a convenience layer, not a security guarantee. Do not publish private generated indexes.

Use the public preparation script before open-source release:

```bash
npm run prepare:public-knowledge
```

It writes:

```text
knowledge/
knowledge/PUBLIC_KNOWLEDGE_MANIFEST.json
knowledge/SANITIZE_REPORT.md
knowledge/.sanitize-report.json
```

Still run a dedicated secret scan and license review before publishing.
