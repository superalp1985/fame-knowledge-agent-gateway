# FAME Knowledge Agent Gateway 使用说明书

这份说明书给第一次使用的人看。它不解释所有内部机制，只讲怎么把软件跑起来，怎么接入 Agent，怎么让它在真实工程里减少工具调用错误，并开始积累自己的知识资产。

项目地址：

```text
https://github.com/superalp1985/fame-knowledge-agent-gateway
```

Release 下载：

```text
https://github.com/superalp1985/fame-knowledge-agent-gateway/releases/tag/v0.1.0
```

## 1. 这个软件是做什么的

一句话：

```text
它是给现有 Agent 用的本地外脑和工具治理层。
```

它主要做四件事：

- 在任务开始前，帮 Agent 对齐目标、项目、科目、路线和上下文预算。
- 在工具调用前，检查路径、作用域、危险动作、工具说明书和 approval token。
- 在失败之后，把错误签名、失败原因、修复路线写回外部记忆，降低重复犯错概率。
- 在长期工程里，把公共知识网、私人项目记忆、多模态资产索引分开管理。

它不是替代 Codex、Claude Code、Cursor、OpenAI Agents SDK、Gemini CLI、OpenHands、SWE-agent 或 Aider，而是放在这些 Agent 旁边，给它们提供路线、记忆和刹车。

## 2. 推荐使用方式

### 2.1 从 Release 下载

打开：

```text
https://github.com/superalp1985/fame-knowledge-agent-gateway/releases/tag/v0.1.0
```

下载：

```text
fame-knowledge-agent-gateway-v0.1.0-portable.zip
```

解压到非系统盘，例如：

```text
<non-system-drive>:\fame-knowledge-agent-gateway
```

然后运行：

```powershell
.\start.ps1
```

或双击：

```text
start.bat
```

启动成功后打开：

```text
http://127.0.0.1:5178/
```

### 2.2 一键安装脚本

也可以下载 Release 里的 `install.ps1`，然后运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1
```

指定安装位置：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1 -InstallDir "<install-path>"
```

## 4. 第一次打开后看哪里

### 4.1 Agent 外脑

默认首页是 `Agent 外脑`。

这里主要看：

- `安全阻断`：当前工具动作是否允许。
- `工具成功率`：近期工具调用反馈。
- `上下文健康`：当前上下文预算是否过高。
- `失败复发`：是否有重复错误签名。
- `同步压力`：记忆和资产索引是否有待写回。
- `Agent 接入`：本机 Agent 是否已经接入。

如果你只想知道系统有没有正常工作，先看这里。

### 4.2 Agent Runtime

进入 `Agent Runtime`，使用首次接入向导。

操作顺序：

1. 选择 `中文开源版` 或 `English open edition`。
2. 选择 Agent 类型，例如 `Codex`、`Cursor`、`Claude Code`、`OpenAI Agents SDK`、`Gemini CLI`、`OpenHands`、`SWE-agent`、`Aider`。
3. 点击 `检查入口`。
4. 点击 `复制接入消息`。
5. 把接入消息发给你的 Agent。
6. 等 Agent 回复已经接入后，由用户确认。

接入后，Agent 应该知道：

- 每次工程任务前先对齐目标和路线。
- 工具调用前必须检查说明、路径、作用域和安全边界。
- 执行后要写回 ToolResultSummary。
- 失败要记录 failure signature。

## 5. 跑一次路线

中文开源版：

```bash
npm run route:chinese-open -- --goal "修复 PowerShell 中文乱码并验证输出" --compact
```

英文版：

```bash
npm run route:english -- --goal "run npm test after confirming package root" --compact
```

`--compact` 的作用是只给 Agent 当前任务需要的路线摘要，不把整张知识网塞进上下文。

## 6. 让 Agent 更稳地调用工具

推荐的工具调用流程是：

```text
Goal
-> scoped route
-> ContextPack
-> ProposedAction
-> ApprovedAction
-> Tool Gateway
-> ToolResultSummary
-> Memory Writeback
```

也就是说，Agent 不应该直接执行高风险工具。

高风险例子：

- 删除文件。
- 移动目录。
- 修改数据库。
- 批量重写代码。
- 对未确认路径执行脚本。
- 在脏工作区里继续覆盖文件。

系统的预期行为：

- 没有工作目录和目标范围时阻断。
- 即使有范围，也要求 ApprovedAction。
- token 被篡改时阻断。
- 工具结果必须摘要写回。

## 7. 看知识网

### 7.1 3D Universe

`3D Universe` 用来看全局结构。

它适合回答：

- 语言树在哪里。
- 某个学科围绕语言树怎么生长。
- 哪些节点是文件、路线、规则、教训。
- 哪些边是健康路线，哪些是负值 FAME 风险路线。

### 7.2 2D Detail

`2D Detail` 用来看局部路线。

它适合：

- 编辑一个模块。
- 新增模块。
- 新增路径。
- 删除路径。
- 查看 FAME edge。
- 把补充知识先提交为 proposal。

## 8. 补充开源知识网

补知识时不要只扔一段资料进去。推荐按这个结构写：

```text
subject
-> abstraction
-> route
-> content unit
-> tool manual
-> verification
-> lesson
-> FAME parameters
```

一个合格知识点最好包含：

- 属于哪个 subject。
- 挂在哪条 route。
- 连接语言树里的哪个意图或术语。
- 解决什么工程问题。
- 需要哪些工具。
- 怎么验证。
- 失败时留下什么教训。
- 是否有 FAME 风险参数。

这样它才不是普通文档，而是 Agent 可以遍历、裁剪和执行的知识路线。

## 9. 建立私人知识资产

公共知识网和私人项目记忆要分开。

推荐结构：

```text
公共知识网：通用、可开源、社区维护
项目记忆 overlay：私有、绑定具体工程
资产数据库：存原始文档、图片、日志、多模态材料
知识网：只保留索引、预览、摘要和路线锚点
```

这样有三个好处：

- 私人资料不会污染公共知识网。
- 原始大文件不会压垮图谱。
- Agent 仍然能通过索引找到相关资料。

项目经验如果要晋升成公共知识，建议先走 review 或 proposal。

## 11. 常见问题

### 11.1 PowerShell 中文乱码

优先用项目自带的一键启动脚本：

```powershell
.\start.ps1
```

它会设置 UTF-8 输出。也可以手动检查：

```powershell
[Console]::OutputEncoding
chcp
```

系统里有 PowerShell 编码探测路线，Agent 处理这类问题时应该先走 route，而不是直接猜命令。

### 11.2 端口被占用

默认端口：

```text
Workbench: 5178
Gateway:   5191
```

如果端口被占用，先关闭旧进程，再重新运行：

```powershell
.\start.ps1
```

### 11.3 Agent 不知道怎么接入

让 Agent 先看：

```text
AGENTS.md
```

然后进入 Workbench 的 `Agent Runtime`，复制对应 Agent 的接入消息。

### 11.4 GitHub Actions 显示红色

先确认 Release 是否已经有安装包。如果 Release 可用，用户下载不受影响。

开发者再检查：

```bash
npm run build:release-assets
```

如果 workflow 修改过，需要 push 到 `main` 后重新跑 Actions。

## 12. 最推荐的实际使用路径

第一次使用可以按这个顺序：

```text
1. 下载 portable zip
2. 运行 start.ps1
3. 打开 http://127.0.0.1:5178/
4. 看 Agent 外脑首页是否 ready
5. 进入 Agent Runtime
6. 选择自己的 Agent
7. 复制接入消息给 Agent
8. 跑一次 route:chinese-open --compact
9. 让 Agent 执行一个小任务
10. 看 ToolResultSummary 和失败教训是否写回
```

如果这条链路跑通，说明这个系统已经可以作为你的 Agent 外部记忆和工具治理层使用。
