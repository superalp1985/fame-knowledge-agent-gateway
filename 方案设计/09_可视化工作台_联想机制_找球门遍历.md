# 可视化工作台、联想机制与“找球门”遍历

## 1. 可视化工作台定位

`Knowledge Workbench` 不是普通图谱浏览器，而是给 agent 外部插件提供三类能力：

```text
看见知识网
补充知识网
调试路线和工具调用
```

它服务四类用户：

- 人类设计者：查看知识网结构、补充 route、审核 patch。
- Agent：按 scope 获取当前可用路线、FAME 状态、工具说明书。
- 工程系统：查看项目进度、失败复发、质量门状态。
- 调试者：复盘一次工具调用为什么被允许或阻断。

## 3. Workbench 主要视图

### 3.1 Route Graph

展示：

```text
基本概念 -> 一级联想 -> 抽象层 -> 规律层 -> 工具层 -> 质量门 -> 返修规则
```

交互：

- 按 subject/domain/route_id 过滤。
- 点击边查看 FAMEEdgeState。
- 点击节点查看来源文件和摘要。
- 支持只展开 top-k 联想。

### 3.2 FAME Heatmap

用颜色表达边状态：

```text
mu 高：绿色
kappa 高：蓝色
nu 高：黄色
delta 高：红色
lambda 高：紫色
rho 高：灰色
freshness 低：虚线/淡色
```

用途：

- 找出高风险路线。
- 找出高失败复发区域。
- 找出值得探索但未验证的高 chi 区域。

### 3.3 Project Overlay

把当前工程状态叠加到知识图谱上：

```text
当前任务正在用哪些 route
当前工具调用属于哪个 route
哪些文件/模块对应哪些工具层节点
哪些质量门卡住了进度
```

### 3.4 Failure Map

按 failure_category 聚合：

```text
bad_args
missing_scope
manual_not_read
permission_required
quality_gate_failed
context_over_budget
route_conflict
stale_knowledge
```

### 3.5 Freshness View

展示：

```text
过期 route
过期工具说明书
长期未验证 edge
外部来源临时证据
```

### 3.6 Traversal Debug View

展示一次“找球门”路径：

```text
goal -> candidate routes -> association expansion -> abstraction filter
-> FAME scoring -> tool gate -> quality gate -> selected path
```

显示每一步：

- 被保留的 top-k。
- 被剪枝的节点。
- 剪枝原因。
- FAME 分数。
- 上下文 token 成本。

## 4. 联想机制设计

建木知识网的联想不是随机发散，而是“第一跳创造 + 抽象约束 + 工程验证”。

### 4.1 联想层级

```text
L0 用户意图联想
L1 route 一级联想
L2 抽象类型联想
L3 工具能力联想
L4 质量风险联想
L5 失败教训联想
L6 跨科目类比联想
```

### 4.2 联想候选生成

候选来源：

```text
first_order_association.yaml
abstraction_to_expression.yaml
tool_capability_map.yaml
failure_summary
route_summary
FAME high-chi edges
历史成功路径
历史失败教训
```

### 4.3 联想过滤

联想不能直接执行，必须经过：

```text
scope filter
abstraction filter
FAME score
quality gate fit
context budget fit
permission check
```

### 4.4 联想收益评分

```text
AssociationScore =
  0.22 * chi
+ 0.18 * epsilon
+ 0.16 * kappa_eff
+ 0.14 * abstraction_fit
+ 0.12 * novelty
- 0.12 * nu
- 0.16 * delta
- 0.08 * rho
- 0.10 * lambda
```

### 4.5 联想边类型

```yaml
AssociationEdge:
  source_id: string
  target_id: string
  association_type:
    semantic
    abstraction
    tool_affordance
    quality_risk
    failure_lesson
    cross_subject_analogy
  scope:
    project_id: string
    subject: string
    route_id: string
  fame_edge_state_ref: string
  evidence_refs: list
```

## 5. “找球门”遍历机制

“找球门”指 agent 在大图谱中寻找能把当前问题推进到可交付结果的目标门。它不是漫游，也不是全图搜索，而是受目标、约束、质量门和 FAME 状态控制的路径搜索。

### 5.1 球门定义

```yaml
GoalGate:
  gate_id: string
  goal_type:
    answer_question
    choose_tool
    fix_failure
    generate_artifact
    pass_quality_gate
    update_knowledge
    resume_project
  success_condition: string
  required_outputs: list
  quality_gates: list
  forbidden_paths: list
  context_budget: int
```

示例：

```text
当前任务：修复工具调用失败
球门：找到最小可执行修复路径，并降低同类失败复发
成功条件：工具重跑成功 + failure_summary 写回 + lambda 降低
```

### 5.2 球门路径

```yaml
GoalPath:
  path_id: string
  start_node: user_intent|project_event|failure_case
  goal_gate: GoalGate
  route_nodes: list
  association_nodes: list
  abstraction_nodes: list
  tool_nodes: list
  quality_gate_nodes: list
  estimated_score: float
  estimated_context_cost: int
  risk_flags: list
```

### 5.3 遍历方式

采用 `Scoped Beam Search + FAME Scoring + Goal Gate Check`：

```text
1. Resolve Scope
   project_id / subject / domain / route_id / task_id

2. Define GoalGate
   明确这轮要进哪个球门

3. Candidate Route Lookup
   从 route shard 找 top-k route

4. Association Expansion
   只展开一级联想和高 chi 边

5. Abstraction Filter
   选择主抽象类型，去掉不匹配联想

6. FAME Scoring
   用 FAMEEdgeState 给路径打分

7. Context Cost Check
   剪掉 token 成本过高路径

8. Tool / Quality Gate Check
   检查工具说明书、权限、质量门

9. Select Path
   输出 GoalPath + ProposedAction

10. Audit / Summary
   记录被选路径和被剪枝原因
```

### 5.4 路径评分

```text
GoalPathScore =
  route_score
+ association_score
+ tool_fit
+ quality_gate_fit
+ freshness
- context_cost_penalty
- risk_penalty
- recurrence_penalty
```

其中：

```text
context_cost_penalty = used_tokens / max_context_tokens
risk_penalty = max(nu, delta)
recurrence_penalty = lambda * repeated_failure_factor
```

### 5.5 剪枝规则

立即剪枝：

```text
scope 不匹配
route_id 缺失
manual 未读且即将调工具
permission_required 但无人确认
delta > 0.65
rho > 0.80 且不是必须重 worker
context_cost 超预算
quality_gate 不允许 final
```

降权不剪枝：

```text
freshness 低但可验证
chi 高但 kappa 低
lambda 高但有明确 fix recipe
```

### 5.6 可视化表现

在 Traversal Debug View 中：

```text
绿色路径：最终选中路线
灰色路径：被剪枝
黄色边：风险高但可验证
红色边：冲突或权限阻断
紫色边：失败教训高 lambda
虚线边：低 freshness
```

## 7. v4 双层图谱交互更新

### 7.1 语言树中心 3D Universe

3D Universe 不再以普通总根为视觉中心，而以 `语言树 / Language Backbone` 为原点。其他知识围绕语言树生长：

```text
语言树中心
  -> 语言入口 / 词汇层 / 语法层 / 语义层
  -> 知识根
  -> 学科分片
  -> sample 文件节点
  -> 跨学科联想边
```

原则：

```text
3D 只承载大局、学科关系、跨域联想和风险热力。
文件节点只展示 sample/top-k，避免大图爆炸。
所有可处理细节进入 2D 局部图。
```

### 7.2 手动观察与双击下钻

```text
单击 3D 节点 -> 选中并显示分片摘要
鼠标拖拽 -> 手动旋转观察
滚轮 -> 缩放
双击 3D 节点 -> 进入对应 2D Detail
```

不使用自动旋转。自动旋转会制造“看起来活跃”的假象，但会干扰用户定位节点和判断结构关系。

### 7.3 2D 局部路线生成

双击 3D 节点后，2D Detail 应根据当前 shard 动态生成局部图：

```text
语言树主干
-> 当前知识分片
-> 抽象与联想
-> 找球门遍历
-> 质量门与强制执行
-> 图形化补知识 proposal
-> 负值 FAME 教训
```

sample 文件作为局部节点展开，承担“证据入口”和“补充目标定位”。

### 7.4 FAME 负值路线视觉规则

负值 FAME 不是简单删除，而是作为路线状态展示：

```text
delta 高 / conflicts_with -> 红色粗虚线，标签“冲突阻断/负值风险”
lambda 高 / failure_count 高 -> 紫色粗虚线，标签“失败教训”
nu 高 / rho 高 / freshness 低 -> 黄色或灰色虚线，标签“待验证/低新鲜度”
```

3D 和 2D 使用同一套 `riskLevel`：

```text
stable | watch | risk | lesson
```

### 7.5 图形化补知识入口

知识补充入口面向人类设计者和 agent 共同使用，采用 preset + proposal 方式，而不是直接编辑核心知识网：

```text
添加路线
添加联想
记录教训
更新工具说明
弃用路线
```

每个 preset 自动填：

```text
patch_type
section
target route_id
target file_path
initial_fame
content_summary
evidence_refs
affected_edges
```

提交后生成 `KnowledgePatchProposal`，必须进入 review 流程。

## 8. v5 2D 模块编辑与完整知识接入

### 8.1 2D 模块编辑视窗

2D Detail 不只是查看图，而是当前 route shard 的局部编辑器：

```text
单击 2D 节点 -> 选中模块
双击 2D 节点 -> 打开模块编辑视窗
编辑 label/kind/summary/source_ref -> 保存为本地草稿
新增模块 -> 在当前模块旁生成 draft node
新增路径 -> 生成 draft edge
删除路径 -> 标记 deprecate_edge proposal
删除模块 -> 删除本地 draft node，并生成弃用 proposal
```

所有动作必须先形成 `KnowledgePatchProposal`，不得直接写核心知识网。

### 8.2 完整知识网接入层次

知识接入分为两层：

```text
public knowledge/:
  开源净化基底，保留安全可提交文本知识。

private knowledge_backup/:
  本地完整知识资产，供工作台调试和路线连接使用。
```

完整接入不是把 19758 个原始文件全部画成节点。应先过滤掉：

```text
.git
node_modules
__pycache__
hf_cache
vendor
outputs/cache/results/leaderboard_runs
source maps / compiled cache
```

再把剩余知识资产接入：

```text
Markdown/YAML/JSON/JSONL/TXT/CSV -> 文本摘要
PDF/PPTX/DOCX/图片/音频/视频/Parquet/SQLite -> asset metadata
route_index.json -> 拆为路线级统计和 2D top-k route 节点
backbone.json -> 语言树层、语言 neuron、抽象规则
associations/*.json -> 跨学科联想和一级联想
entries/neurons/rules -> 学科知识生长内容
```

### 8.3 语言树补接原则

语言树必须从“4 个层节点”升级为：

```text
语言中枢
-> 入口层
-> 词汇层 / 语法层 / 语义层
-> specific_neurons
-> route_index subjects/domains/routes
-> associations cross-domain links
-> 2D 局部 route samples
```

3D 仍然只展示中心、层级、学科分片、sample 和跨域边；2714 条 route 不全量铺到 3D，而是在 2D 按 scope/top-k 展开。

### 12.2 Semantic anchors

The first anchor set is:

```text
语言树中枢
正规学科分类
抽象与模型层
联想创造层
工具治理层
质量与记忆层
```

These anchors deliberately separate:

```text
formal taxonomy
abstraction hierarchy
Jianmu association route
agent execution governance
```

This prevents the knowledge net from becoming either a file index or a flat search library.

### 12.3 Auto-fit rule

The first implementation may use lightweight keyword and token scoring so it can run locally without embeddings:

```text
semantic_fit =
  0.42 * token_overlap
+ 0.30 * keyword_hit
+ 0.12 * priority
+ route_type_boost
```

Later it can be upgraded with embeddings, UMAP/HDBSCAN clustering, or GraphRAG/LightRAG community summaries.

### 12.4 Review boundary

Semantic auto-fit must not directly rewrite the core knowledge net:

```text
high confidence:
  can be shown as suggested anchor

medium confidence:
  can be used for traversal hint

review confidence:
  must become KnowledgePatchProposal
```

### 12.5 3D zoom stability

3D controls now keep the user requirement:

```text
left drag: pan
right drag: rotate
wheel: zoom
double click node: open 2D detail
auto rotate: disabled
```

But zoom stability is improved by:

```text
zoomToCursor = true
screenSpacePanning = true
maxTargetRadius = 48
zoomSpeed = 0.85
panSpeed = 0.82
```

This reduces the problem where repeated pan makes the OrbitControls target drift so far that wheel zoom appears stuck.

Workbench v12 adds an `Assets` view for multimodal knowledge sources. This view is not a heavy media library inside the graph; it is a database-backed preview and routing surface.

### 15.1 Light index boundary

```text
Knowledge graph:
  show AssetIndexNode
  show preview summary
  show route_refs / subject_refs
  show FAME summary
  show db_ref / object_ref / text_ref

Asset store:
  keeps raw image/pdf/log/table/audio/video
  keeps thumbnail/OCR/ASR/caption/extracted text
  keeps embedding refs
  keeps extraction runs and FAME history
```

The Workbench must make this boundary visible through a `Light Index Boundary` panel so an agent cannot mistake preview data for full raw evidence.

### 15.2 View responsibilities

The `Assets` view must show:

```text
Multimodal Asset Index:
  asset cards
  modality badges
  preview type
  route anchor hint

Inspector:
  light_index_only policy
  modality counts
  selected asset summary
  FAME summary meters
  database references
  route anchors
  evidence edges
  extraction runs
  FAME history
```

### 15.3 Search behavior

Search now includes multimodal asset indexes:

```text
asset_id
label
summary
caption
tags
route_refs
subject_refs
db_ref
object_ref
extracted_text_ref
```

Opening an asset search result switches to `Assets` and selects the asset card. Queries with explicit asset intent such as `asset`, `multimodal`, `db_ref`, `object_ref`, `text_ref`, `thumbnail`, or `route_index` get an asset-ranking boost while still allowing core knowledge route/file matches to remain visible.

### 15.4 Context rule for agents

Agent context packs should include only:

```text
asset_id
label
summary
caption
route_refs
subject_refs
FAME summary
db/object/text refs
```

Raw media, full PDF text, OCR dumps, ASR transcripts, embeddings and full extraction logs are lazy-loaded only after GoalGate and Tool Governance approve the need. After the task finishes, raw payloads are released and only a summary/log reference remains.

## 16. v12.1 Manual knowledge edit database sync

用户手动补充、编辑、删除知识模块或路径时，Workbench 必须同步提示资产数据库需要发生什么变化。这个过程不直接写库，而是生成可审核的同步项。

### 16.1 Trigger points

```text
2D Detail:
  save module -> edit_route proposal -> refresh_asset_index sync
  add module -> add_route proposal -> append_asset_index sync
  add path -> add_edge proposal -> upsert_asset_edge sync
  delete path/module -> deprecate_edge proposal -> append_asset_fame_history sync

Patch Entry:
  submit KnowledgePatchProposal -> AssetDbSyncItem preview

Assets:
  selected asset shows related sync items
```

### 16.2 UI surfaces

```text
Topbar:
  sync pending count

Assets view:
  Manual Sync Boundary
  selected asset Manual Asset DB Sync list
  db refs and guardrails

Patch Entry:
  Asset DB Sync Preview
  source proposal / target asset / operation / status
```

### 16.3 Sync display contract

Each sync item must show:

```text
operation
status
source_proposal_id
target_asset_id
route_id
file_path
db_refs
proposed fields
guardrails
```

This allows a human or agent to see whether a manual knowledge edit will refresh asset index, edge anchor or FAME history.

### 16.4 Anti-fork rule

```text
KnowledgePatchProposal is the knowledge-side pending truth.
AssetDbSyncItem is the database-side pending truth.
ApprovedAction is the execution permission.
Summary/FAME history is the replay record.
```

The Workbench must not let users update visual knowledge and asset database independently without a visible sync item. If a manual edit cannot be matched to an existing asset, the system creates a draft asset index target and marks it for review.

```text
topbar sync pending count visible: pass
Assets inspector Manual Sync Boundary visible: pass
Patch Entry Asset DB Sync Preview visible: pass

```

## 17. v13 理论增强视图

v13 的 Workbench 不新增“更大的全图”，而是给现有 Agent Runtime、FAME Heatmap、GoalGate、Project Memory、Assets 增加动态调试层。

### 17.1 FAME Dynamics View

用于展示路线状态随工程反馈变化：

```text
E(t) 当前 8 维 FAME
E_target 目标状态
xi 惯性
freshness / half_life
recent event deltas
predicted_E_delta vs observed_E_delta
```

交互：

```text
点击 FAME edge -> 打开时间序列 sparkline
点击时间点 -> 查看 event_ref / evidence_refs / update_reason
高 xi 边显示稳定标记
低 xi 边显示探索标记
```

### 17.2 SCAC Convergence View

GoalGate 视图新增真实反馈收敛：

```text
distance_before
distance_after
kappa_scac
posterior_entropy_before
posterior_entropy_after
entropy_drop
feedback_gain
```

视觉规则：

```text
kappa_scac < 1:
  绿色收敛线

kappa_scac >= 1 and entropy_drop <= 0:
  红色不收敛阻断线

连续不收敛:
  强制显示 re-scope / human_review 建议
```

### 17.3 Route Posterior View

“找球门”遍历不只显示被保留/剪枝的路线，还显示候选路线后验变化：

```text
route prior
route posterior
entropy contribution
policy_pass
last_feedback_ref
selected_route_id
```

这能解释 agent 为什么从“看起来相关”的路线转向“更能收敛”的路线。

### 17.4 Full Memory Retention View

Project Memory 和 Summary Memory 新增上下文表达队列：

```text
include_summary
pin_for_goal
lazy_load_raw
audit_only
promote_candidate
```

每条记忆显示：

```text
importance
freshness
reuse_count
storage_ref
summary_ref
context_action
reason
```

上下文打包时优先读取 high-alpha / fresh / reused 摘要或 refs，低 context_attention 记录默认只显示外部存储位置；原始记录仍全量保留。

### 17.5 Temporal Truth View

Freshness View 升级为时序真实性视图：

```yaml
TemporalTruthEdge:
  edge_id: string
  valid_from: datetime
  valid_to: datetime|null
  observed_at: datetime
  last_verified_at: datetime
  invalidated_by_ref: string|null
  provenance_refs: list
  fame_state_ref: string
```

视觉规则：

```text
valid_now: 实线
expired: 淡色虚线
invalidated: 红色断线
unverified_recent: 黄色虚线
verified_recent: 蓝/绿实线
```

### 17.6 Sync Outbox View

v12.1 的 `AssetDbSyncItem` 应升级为可回放 outbox：

```text
pending
approved
sent
applied
failed
replayed
blocked
```

显示链路：

```text
KnowledgePatchProposal
-> AssetDbSyncItem
-> ApprovedAction
-> OutboxEvent
-> Asset DB write
-> FAME history / trace
```

Workbench 必须能解释任意一条资产索引为什么没有同步、同步到哪一步、是否可重放。

## 18. v13 找球门遍历升级

原遍历：

```text
Scoped Beam Search + FAME Scoring + Goal Gate Check
```

升级为：

```text
Scoped Beam Search
+ Route Posterior
+ FAME Dynamics
+ SCAC Physical Feedback
+ Full Memory Retention / Context Distillation
+ Enforcement
```

流程：

```text
1. WorkStartAlignment
2. Resolve Scope
3. Define GoalGate
4. Candidate Route Lookup
5. Load high-alpha summaries
6. Compute route prior
7. Association Expansion
8. FAME Dynamics Scoring
9. Context Cost Check
10. Enforcement Dry-run
11. Execute ApprovedAction
12. Observe PhysicalFeedbackEvent
13. Update Route Posterior
14. Compute kappa_scac / entropy_drop
15. Write Summary + FullMemoryRetentionState
16. Update FAMETimeseriesPoint
17. Decide continue / re-scope / stop / human_review
```

新增剪枝：

```text
kappa_scac >= 1 and entropy_drop <= 0
posterior too low and chi not high
context_attention too low unless audit mode
TemporalTruthEdge invalidated
sync_drift_rate above threshold for asset-dependent route
```

新增降权：

```text
posterior low but chi high
expired but verifiable
high lambda but has proven fix recipe
high alpha lesson useful for avoiding repeat failure
```
