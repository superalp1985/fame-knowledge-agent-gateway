## 9. v6 runtime index rule

Workbench must not bundle the full knowledge index into the main frontend chunk.

```text
src/generated/*.ts:
  type definitions + runtime loaders only

public/generated/*.json:
  full knowledge index / route stats / association graph

UI boot:
  lightweight 3D first -> runtime index ready -> full search / shard stats / 2D route samples
```

Current verified scale:

```text
5559 indexed files
2714 routes
39 shards
255 universe nodes
287 universe links
main JS entry: about 1.1 MB
```

## 10. v9 agent runtime plugin rule

Workbench v9 adds an agent-facing runtime layer. The project positioning is now explicit in implementation, not only in documents:

```text
FAME Knowledge Agent Gateway
  = universal external agent plugin
  + external brain runtime
  + knowledge route controller
  + tool governance gateway
```

### 10.1 Adapter boundary

The gateway exposes multiple adapter forms:

```text
MCP Server:
  primary agent interface
  exposes tools/resources/prompts

HTTP API:
  remote agent and web app interface

CLI Adapter:
  local automation and pipeline interface

IDE Adapter:
  editor state -> project scope -> route hint

Workflow Adapter:
  long task, reminder, resume, replay and human review
```

These adapters never replace the reasoning layer. They only connect agents to the runtime.

### 10.2 Agent thinking pipeline

Every agent request should be reduced to this visible pipeline:

```text
WorkStartAlignment
-> Scope Resolve
-> Semantic Route
-> GoalGate Traversal
-> Tool Governance
-> Context Pack
-> Memory Update
```

This pipeline is exposed in Workbench `Agent Runtime` view and must also be exposed by future MCP/HTTP debug endpoints.

### 10.3 Semantic auto-fit

The knowledge net should not rely only on folder paths. Each route creates a semantic fingerprint:

```text
SemanticFingerprint =
  title
  + subject/domain
  + route_id
  + keywords
  + content summary
  + selected 2D node summary
  + FAME state
```

Then the runtime proposes anchor links:

```text
language_tree
formal_taxonomy
abstraction
association
tool_governance
quality_memory
```

Initial scoring:

```text
semantic_fit =
  0.42 * token_overlap
+ 0.30 * keyword_hit
+ 0.12 * priority
+ route_type_boost
```

Low confidence links are not written to the core knowledge net. They become review proposals.

### 10.4 Enforcement preview

The Workbench now previews `ProposedAction -> ApprovedAction` checks:

```text
scope_check
goalgate_check
manual_check
fame_check
context_check
```

Future real tool execution must use the same shape:

```text
Agent -> ProposedAction -> Enforcement Kernel -> ApprovedAction -> Tool Gateway
```

### 10.5 Context pack

Agent runtime must show what enters and leaves context:

```text
retain:
  scope
  goal
  selected route node
  selected FAME edges
  top semantic anchors

release:
  raw tool manual after call
  full search results
  unselected edges
  raw logs after summary
```

This keeps the system from becoming a retrieval dump.

## 11. v10 project memory overlay rule

Project Memory Graph is a separate engineering memory net for actual project execution. It is not part of the core knowledge net.

```text
Core Knowledge Net:
  read-only stable knowledge
  language tree
  taxonomy
  abstraction and general route policy

Project Memory Graph:
  project-specific task, decision, module, artifact, tool result, failure lesson, quality gate, context summary

Promotion Candidate:
  reviewed bridge from project lesson to core knowledge
```

### 11.1 Storage layout

```text
memory/projects/{project_id}/
  project_manifest.json
  project_graph.jsonl
  project_edges.jsonl
  fame_overlay.jsonl
  tool_invocation_summary.jsonl
  failure_lessons.jsonl
  context_summaries/
  promotion_candidates/
```

### 11.2 Write policy

```text
ProjectMemoryGraph:
  writable by project runtime

Core Knowledge Net:
  read-only by default
  writable only through KnowledgePatchProposal / promotion review

Session Scratch:
  disposable raw tool output and temporary manual
```

### 11.3 FAME layering

Project execution updates project overlay FAME, not core FAME:


## 14. v13 theory-driven mechanism upgrade rule
