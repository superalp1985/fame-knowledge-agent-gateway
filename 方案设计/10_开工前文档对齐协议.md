# 开工前文档对齐协议

## 1. 目的

每次开始新工作前，必须先对齐项目文档，防止 agent 依赖旧上下文、遗漏最新设计、跳过强制流程或把临时想法当正式方案。

本协议是本项目的工作流入口。

## 2. 必读文档顺序

每次开工前按顺序读取：

```text
1. 01_FAME工程图谱记忆组织器方案.md
2. 08_完整版实施蓝图.md
3. 09_可视化工作台_联想机制_找球门遍历.md
4. 07_差异化_遍历效率_评估指标.md
5. 04_FAME公式与参数.md
6. 05_调研摘要.md
```

如果任务涉及图纸，额外读取：

```text
02_架构图.mmd
03_状态机图.mmd
06_架构可视图.svg
```

如果任务涉及知识网内容，额外读取：

```text
knowledge_backup/BNAI智能agent知识网/README_FOR_AGENT.md
knowledge_backup/BNAI智能agent知识网/knowledge_hierarchy.md
knowledge_backup/BNAI智能agent知识网/tool_aware_reasoning.md
knowledge_backup/BNAI智能agent知识网/tool_capability_map.yaml
```

## 3. 开工前必须输出的对齐摘要

正式执行前，agent 应形成一段内部或可见摘要：

```yaml
WorkStartAlignment:
  project_positioning: Agent 万用外部插件 / 外脑运行时 / 工具治理网关
  current_task: string
  relevant_docs_read: list
  active_scope:
    project_id: string
    subject: string
    route_id: string
    task_id: string
  active_goal_gate:
    goal_type: string
    success_condition: string
  required_modules: list
  enforcement_required: true
  context_budget_strategy: summary_first
  expected_outputs: list
```

## 4. 开工前检查清单

```text
[ ] 是否确认当前任务属于方案设计、实现、调试、可视化、知识补充、评估中的哪类？
[ ] 是否确认 project_id / subject / route_id / task_id？
[ ] 是否定义 GoalGate？
[ ] 是否知道本次是否需要工具？如果需要，是否只准备按需读取工具说明书？
[ ] 是否需要 Enforcement Kernel 检查？
[ ] 是否需要 Knowledge Workbench / 可视化更新？
[ ] 是否需要更新 Mermaid / SVG 图纸？
[ ] 是否需要写入 summary / log / patch proposal？
[ ] 是否有人工确认边界？
```

## 5. 禁止事项

```text
禁止不读主方案直接改设计。
禁止绕过 08 完整实施蓝图新增模块。
禁止只根据聊天记忆更新图纸。
禁止把工具调用细节长期写入上下文。
禁止不定义 GoalGate 就做图遍历。
禁止不经 proposal/review 直接改知识网核心内容。
禁止让 LLM 直接执行工具；必须走 ProposedAction -> ApprovedAction。
```

## 6. 对齐后的执行顺序

```text
Read Docs
-> WorkStartAlignment
-> Define GoalGate
-> Scope / Route / FAME State
-> Decide Whether Tool Is Needed
-> If Tool Needed: Read Tool Manual Lazily
-> ProposedAction
-> Enforcement Kernel
-> Execute / Update / Summarize
-> Update Docs / Diagrams / Logs
```

## 7. 文档更新规则

每次改设计时：

```text
主方案变更 -> 更新 01
实施结构变更 -> 更新 08
可视化/遍历变更 -> 更新 09
评估指标变更 -> 更新 07
公式参数变更 -> 更新 04
外部技术依据变更 -> 更新 05
图结构变更 -> 更新 02/03/06
工作流变更 -> 更新 10
```

## 8. 上下文健康规则

开工前不全量塞入所有文档。只读取：

```text
当前任务相关章节
最新修改摘要
必要 schema
必要图源
```

长文档只引用摘要，必要时展开原文。

## 9. 完成后的收尾

每次工作完成后：

```yaml
WorkEndSummary:
  files_changed: list
  design_decisions: list
  diagrams_updated: list
  unresolved_questions: list
  next_goal_gate: string
  context_release_summary: string
```

该摘要可以作为下一次 `WorkStartAlignment` 的输入。
