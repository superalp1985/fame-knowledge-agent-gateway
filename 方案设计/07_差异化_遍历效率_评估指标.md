# 差异化、遍历效率与评估指标补充

## 1. 调研结论

现有开源项目各有强项：

- Graphiti/Zep：temporal knowledge graph，适合事实随时间变化、旧事实失效但保留历史。
- GraphRAG：抽取图谱、建立 community hierarchy、生成 community summaries，适合大规模文档的 local/global search。
- Mem0：强调 token-efficient memory，用较少上下文维持记忆能力。
- LangGraph：提供状态机、checkpoint、long-term memory store、namespace 组织。
- MCP/code graph：适合暴露本地工具、代码结构和资源。

这些项目的共同问题是：它们解决“记忆、检索、执行”，但不解决建木式的“抽象联想路由 + 工程质量闭环 + FAME 动态真实性”。

## 2. 我们的明显差异性

### 2.1 FAME 动态边状态

普通系统记录事实：

```text
工具 X 失败过
用户喜欢 Y
项目使用 Z
```

本系统记录关系状态：

```text
在 project_id=P / subject=S / route_id=R 下，
知识路线 A 指向工具 B 的关系当前是否可靠。
```

每条边都有：

```text
mu, chi, epsilon, kappa, nu, delta, rho, lambda, xi, freshness
```

这使系统能表达：

- 有些知识是对的，但当前工程阶段不好用。
- 有些路线失败过，但仍是重要教训。
- 有些工具不是不能用，而是需要更窄 scope 或更高质量门。
- 有些联想值得探索，但不能直接进入执行。

### 2.2 建木知识网思考链

现有 memory 多数是事实召回。本系统是思考流程：

```text
概念定位 -> 一级联想 -> 抽象判型 -> 稳定规律 -> 工具层 -> 工程约束 -> 质量门 -> 返修
```

它不是把知识网当文档库，而是把知识网当工程组织器的认知骨架。

### 2.3 工程进度同步

系统的记忆对象是工程现场：

```text
文件、模块、调用链、工具调用、测试、构建、失败、修复、manifest、review、阶段摘要
```

每次工程事件都更新图谱和 FAME 状态。

### 2.4 上下文健康

本系统不追求最大召回，而追求：

```text
最小必要上下文 + 可恢复日志 + 可检索摘要 + 可审计 FAME 更新
```

解决问题后，完整过程留在日志，不长期占上下文。

## 3. 遍历效率设计

### 3.1 Scope First

所有查询必须先被 scope 限制：

```yaml
scope_key:
  project_id
  subject
  domain
  route_id
  task_id
  phase
  artifact_kind
```

默认不得全图遍历。

### 3.2 分层索引

```text
project_index:
  project_id -> active tasks, changed files, active routes

subject_index:
  subject/domain -> route shards

route_index:
  route_id -> abstraction, tools, quality gates, lessons

tool_index:
  tool_id -> success/failure/fix history

failure_index:
  failure_category -> fix recipes, lessons

summary_index:
  route_id/task_id -> compressed summaries
```

### 3.3 Route Shard

大图谱按以下粒度切片：

```text
project_id / subject / domain / route_id
```

每个 route shard 保留轻量索引：

```yaml
route_shard:
  route_id
  subject
  domain
  keywords
  first_order_association_summary
  primary_abstractions
  tool_policy_summary
  quality_gate_summary
  recent_fame_summary
  recent_lessons
  raw_refs
```

### 3.4 Beam Search 而非全图 BFS

```text
候选 route top_k
-> 抽象 top_k
-> 工具 top_k
-> lesson top_k
```

默认参数：

```yaml
route_top_k: 8
abstraction_top_k: 3
tool_top_k: 5
lesson_top_k: 5
max_hops_fast_path: 2
max_hops_full_path: 5
max_raw_logs_loaded: 3
```

### 3.5 熔断规则

出现以下情况停止扩展：

```text
delta > 0.65
nu > 0.75 and kappa_eff < 0.45
lambda > 0.70 and failure_count >= 3
rho > 0.80
permission_required = true
```

### 3.6 Summary Cache

任务结束写三种摘要：

```text
context_summary：下次进上下文的最小状态。
route_summary：这次为什么走这条路线。
failure_summary：失败、修复、教训。
```

检索优先级：

```text
summary cache -> scoped graph -> raw log
```

## 4. 评估指标

### 4.1 Tool Success Rate

```text
tool_success_rate = successful_tool_calls / total_tool_calls
```

按 `project_id/tool_id/route_id/phase` 分组。

### 4.2 Failure Recurrence Reduction

```text
failure_recurrence_rate =
  repeated_failure_cases_same_category / total_failure_cases
```

```text
failure_recurrence_reduction =
  1 - recurrence_after_fame / recurrence_before_fame
```

### 4.3 Context Token Saving

```text
context_token_saving =
  1 - tokens_scoped_summary / tokens_full_context
```

同时记录成功率，防止通过少读上下文造成质量下降。

### 4.4 Route Hit Quality

```text
route_hit_quality = accepted_routes / proposed_routes
```

accepted 来源：

- 用户确认。
- 工具成功。
- 质量门通过。
- 后续任务复用成功。

### 4.5 Quality Gate Pass Rate

```text
quality_gate_pass_rate =
  artifacts_passed_review / artifacts_reviewed
```

### 4.6 Failure-to-Fix Cycle Time

```text
failure_to_fix_time =
  fixed_at - failed_at
```

衡量 FAME + fix ticket 是否缩短返修路径。

### 4.7 Human Gate Precision

```text
human_gate_precision =
  necessary_human_confirmations / all_human_confirmations_triggered
```

避免过度打断。

### 4.8 FAME Calibration Error

用路线评分预测成功概率：

```text
p_success = sigmoid(Score(route))
```

按概率桶计算：

```text
calibration_error =
  mean(abs(predicted_success_rate - observed_success_rate))
```

### 4.9 Resume Efficiency

```text
resume_efficiency =
  time_to_resume_from_summary / time_to_resume_from_full_logs
```

越低越好。

### 4.10 Exploration Yield

```text
exploration_yield =
  useful_new_routes_or_fixes / high_chi_explorations
```

用于校准 `chi`，防止无意义发散。

## 5. 最小 A/B 实验

对比：

```text
A 组：普通 agent + 工具调用
B 组：建木路由 + FAMEEdgeState + scoped summary + quality gate
```

任务集：

- 代码理解。
- 工具调用。
- 失败修复。
- 多步骤工程任务。
- 文档/图表/多模态产物。

采集：

```text
tool_success_rate
failure_recurrence_rate
context_tokens
route_hit_quality
quality_gate_pass_rate
human_gate_precision
failure_to_fix_time
resume_efficiency
exploration_yield
```

## 6. 外部参考

- GraphRAG：hierarchical graph + community summaries，用于大图谱分层摘要。
- Graphiti/Zep：temporal knowledge graph、事实有效期和 provenance。
- Mem0：token-efficient memory，用较少上下文保持记忆质量。
- LangGraph：namespace/store/checkpoint，可承载状态机与长期记忆。

## 7. v13 理论增强后的差异点

本项目下一步差异化不再只是“图谱 + 记忆 + 工具治理”，而是形成可测量闭环：

```text
FAME 时间动力学:
  每条路线保存 E(t)、E_target、xi、freshness、事件来源和校准误差。

SCAC 物理反馈收敛:
  每次工具/测试/浏览器/人工反馈都计算 kappa_scac 和 posterior entropy drop。

Onto-plasticity 全量记忆保留:
  记忆按情绪标记 alpha、上下文半衰期 tau_eff、复用价值和上下文压力决定摘要、引用、固定或懒加载；底层记录不删除。

Temporal Truth:
  知识边记录 valid_from、valid_to、observed_at、last_verified_at 和 invalidated_by。

Event-sourced Sync:
  手动知识编辑、资产库同步、FAME 历史和 ApprovedAction 均作为可回放事件。
```

这使系统区别于普通 GraphRAG/Agent Memory：

```text
GraphRAG 负责大图摘要和问答。
Graphiti 负责时序事实。
Mem0 负责通用记忆。
LangGraph 负责状态机。
MCP 负责插件连接。

FAME Knowledge Agent Gateway 负责：
  抽象联想路线在工程反馈中是否收敛、是否可靠、是否该继续、是否只保留为审计引用。
```

## 8. v13 新增遍历效率机制

### 8.1 Route Posterior

GoalGate 不只选 top-k route，还维护候选路线后验概率：

```yaml
RoutePosteriorState:
  state_id: string
  project_id: string
  task_id: string
  goal_gate_id: string
  candidates:
    - route_id: string
      prior: float
      posterior: float
      entropy_contribution: float
      policy_pass: bool
      last_feedback_ref: string
  entropy: float
  selected_route_id: string
```

更新：

```text
p_{t+1}(route_i) =
  normalize(
    p_t(route_i)
  * Phi(feedback_t | route_i)
  * I(policy_pass_i)
  )
```

### 8.2 SCAC 剪枝

新增剪枝规则：

```text
kappa_scac >= 1 and entropy_drop <= 0:
  当前路线没有从真实反馈中收敛，禁止继续扩展。

two_consecutive_non_convergent_feedback:
  强制 re-scope 或 human_review。

posterior < posterior_floor and chi not high:
  剪枝。

posterior < posterior_floor and chi high:
  降权保留为探索候选，不能直接执行工具。
```

### 8.3 Full Memory Retention 上下文优先级

检索优先级升级为：

```text
pinned / high-alpha summary
-> fresh route shard
-> route posterior candidates
-> scoped project memory
-> archived summaries
-> raw logs lazy load
```

默认不把低 `context_attention` 记录放入当前上下文，除非 GoalGate 明确进入审计、复盘或失败追溯；底层原始记忆仍全量保留。

## 9. v13 新增评估指标

### 9.1 SCAC Contraction Rate

```text
scac_contraction_rate =
  count(kappa_scac < 1) / total_feedback_events
```

衡量真实反馈是否让路线接近球门。

### 9.2 Posterior Entropy Drop

```text
posterior_entropy_drop_avg =
  avg(H_before - H_after)
```

衡量反馈是否减少路线不确定性。

### 9.3 Non-convergent Route Recurrence

```text
non_convergent_route_recurrence =
  repeated(kappa_scac >= 1 route) / total_route_attempts
```

目标是持续下降。

### 9.4 FAME Inertia Calibration Error

```text
fame_inertia_calibration_error =
  mean(abs(predicted_E_delta - observed_E_delta))
```

用于判断 `xi` 是否过高或过低。

### 9.5 Context Distillation Saving

```text
context_distillation_saving =
  1 - context_loaded_tokens / raw_memory_tokens
```

必须与成功率共同观察，避免过度摘要导致关键证据没有进入上下文。

### 9.6 Useful Memory Retention

```text
useful_memory_retention =
  reused_retained_memories / all_retained_memories
```

衡量全量保留记忆中被摘要、引用或懒加载的部分是否真有用。

### 9.7 Sync Drift Rate

```text
sync_drift_rate =
  unsynced_or_conflicting_asset_indexes / total_asset_indexes
```

用于评估手动知识网编辑和资产数据库是否出现漂移。

### 9.8 Enforcement Bypass Block Rate

```text
enforcement_bypass_block_rate =
  blocked_bypass_attempts / total_bypass_attempts
```

用于验证 agent 不能绕过 ProposedAction -> ApprovedAction -> Tool Gateway。
