# 工程记忆案例录入规范

工程记忆案例用于训练 Agent 的落地经验，但不能污染核心知识网。

## 两层结构

```text
核心知识网
-> 稳定学科结构
-> 通用工具规则
-> 通用 PowerShell 失败模式

工程记忆 overlay
-> 项目目标
-> 决策过程
-> 工具调用轨迹
-> 测试证据
-> 失败教训
-> 可推广候选
```

## 公共开源案例选择标准

可以优先选择：

- 有清晰 issue、PR、commit、CI 结果的项目。
- 能体现工程决策和失败修复过程的项目。
- 涉及工具调用、安全脚本、构建发布、测试回归的项目。
- 许可证清晰，允许引用摘要和链接。

不直接收录：

- 大段源码复制。
- 未公开讨论记录。
- 含密钥、路径、用户数据的日志。
- 许可证不明的材料。

## 案例字段

案例写入 `project-memory-cases/*.json` 或数据库时，应包含：

```json
{
  "case_id": "case-example",
  "source_project": "owner/repo",
  "source_urls": [],
  "license": "unknown",
  "project_goal": "",
  "problem": "",
  "route_refs": [],
  "tool_events": [],
  "evidence": [],
  "lessons": [],
  "fame_updates": [],
  "promotion_status": "overlay_only"
}
```

## 晋升为通用知识

工程记忆可以晋升为核心知识，但必须经过人工审核：

1. 是否脱离具体项目仍成立。
2. 是否有足够证据。
3. 是否不会泄漏私有信息。
4. 是否不违反许可证。
5. 是否能写成通用 route、rule 或 lesson。

晋升后，核心知识网只保存通用摘要和来源链接，原始案例仍留在 overlay。
