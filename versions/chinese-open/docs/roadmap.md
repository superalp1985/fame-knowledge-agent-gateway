# 路线图

## 当前阶段：中文开源核心骨架

- 建立语言树中枢。
- 建立逻辑、数学、计算机科学、Agent 工具调取、PowerShell 安全语法六个分支。
- 录入确定性强的目录级骨架、抽象层、路由规则、来源登记和第一批摘要级知识单元。
- 保持图谱轻量，详细内容进入数据库、规则库和索引库。
- 建立 `database/content_index.json`，用于按学科、来源、路线和关键词按需读取。

## 当前收口：工具稳定性与大局观

开源主力范围收口为两件事：

1. 工具调用更稳：工具动作契约、高频坑位预检、结果摘要、失败签名和负值 FAME 教训。
2. 思考方式更稳：找球门逆推、全局态势模型、思考层级、按需图遍历和上下文裁剪。

下一步只补能直接提升这两件事的内容，不继续扩大通用学科范围。

## 后续补充顺序

1. PowerShell、Git、Node/npm、Python、JSONL/YAML、网络下载、数据库同步的高频错误模式。
2. 每类错误绑定一个最小工具动作契约、一个失败签名和一个验证方式。
3. 用 `tests/agent-effect-smoke.mjs` 和运行时 smoke 验证接入便利性和上下文健康。
4. 逻辑、数学、计算机科学、语言树保留骨架和必要抽象层，更多学科内容交给社区逐步扩展。

## 内容扩充原则

- 优先补能直接让 Agent 少犯错的知识。
- 优先使用权威、稳定、可公开引用的来源。
- 知识网只放轻量导航和摘要，详细内容放数据库。
- 外部正文、词典和教材内容在许可证核验前不得导入。
- 横向联想只迁移结构和方法，不把未经验证的事实写成知识。
- 失败案例保留为 lesson 或负值 FAME，不做记忆蒸发。
- 不追求开源首版补全所有学科内容；首版必须把工具调用和高频错误域做完整。

## 后续阶段：工程记忆案例

- 从公开开源项目中选择高价值案例。
- 只记录摘要、链接、决策路线、工具事件、测试证据和教训。
- 作为 project-memory overlay 存放。
- 经审核后，把通用经验晋升为核心知识网的 rule 或 lesson。

## 发布前检查

- 所有外部资料都有来源登记。
- 许可证状态为 `approved` 或 `pending_reference_only`。
- 无私有路径、密钥、数据库和未清理日志。
- schema 校验通过。
- release check 通过。
